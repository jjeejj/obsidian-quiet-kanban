# 更新与备份恢复

本篇区分插件更新、看板转换备份和文档删除。

## 手动更新插件

1. 关闭正在进行的配置或编辑草稿。
2. 备份插件目录中的 `main.js`、`manifest.json`、`styles.css`，以及需要保留的 `data.json`。
3. 用同一新版本的三个产物替换旧产物。
4. 重新加载插件，必要时重新打开看板。

不要用空的 `data.json` 覆盖原文件。它保存插件设置和详情页记录；单看板配置主要存放在 `.base` 文件中。

自动更新安装命令见[开发与测试](development_zh.md)。

## 分清两类备份

| 备份 | 内容 | 默认位置 |
| --- | --- | --- |
| 安装脚本的旧产物备份 | 被替换的插件发布文件 | `.obsidian/plugins/.quiet-kanban-dev-backups/<时间戳-随机ID>/` |
| 看板转换备份 | 转换前的 `.base` 原始文本 | `.obsidian/plugins/quiet-kanban/backups/` |

这两类备份都不是整库笔记备份。自定义配置目录时，用实际配置目录替换 `.obsidian`。

## 还原插件文件

从安装脚本输出的备份目录取出旧产物，复制回：

```text
<配置目录>/plugins/quiet-kanban/
```

只恢复备份中实际存在的发布文件，然后重新加载插件。安装脚本本身不会在失败后自动回滚。

## 还原转换前的看板

1. 找到对应转换备份 JSON。
2. 检查 `path` 是否为目标看板。
3. 读取 `content` 字段的解码文本，原样写回对应 `.base` 文件。
4. 重新打开看板，确认已恢复原生视图。

不要把整个备份 JSON 直接覆盖到 `.base` 文件；需要的是 `content` 中的原始文本。

## 配置与文档的恢复范围

- 改字段布局、别名、样式，只改变显示配置，不批量改写文档。
- 拖拽、快捷编辑、重命名、移动会操作实际文档。
- 删除文档是否可恢复，取决于 Obsidian 的删除设置。
- 停用或卸载插件不会自动把自定义看板转换回原生看板。

重要文档仍应使用自己的仓库备份方案。
